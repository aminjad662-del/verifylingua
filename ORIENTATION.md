# ORIENTATION.md — Architecture & Pipeline Map

## 1. System Map

- **Framework**: Next.js 15.2.0 (App Router), React 19.0.0, TypeScript 5.9.3.
- **Runtimes**:
  - Node.js 22.16.0 (local / server runtime).
  - Cloudflare Pages / Workers (`_worker.js` generated by `scripts/build-cloudflare.js`) for edge deployment.
- **Package Manager**: `pnpm@9.15.0` (`packageManager` field in `package.json`).
- **Upload Handlers**:
  - `app/api/translate/upload/route.ts` (Next.js server route supporting `multipart/form-data` and `application/json` base64).
  - `scripts/build-cloudflare.js` (Edge router intercepting `pathname === '/api/translate/upload'`).
- **OCR / Layout Extraction**:
  - `lib/translation/spatial.ts` (`extractPdfSpatialBlocks`, `extractImageSpatialBlocks` using `pdf-lib`, decompressed PDF streams, and Jimp).
  - `lib/agents/03_extractor.ts` (`ExtractionAgent` normalizing coordinates to `[ymin, xmin, ymax, xmax]`).
  - Edge worker: Calls Gemini Vision API (`models/gemini-2.5-flash:generateContent`) returning normalized `[0..1000]` bounding boxes.
- **Translation Calling Layer**:
  - `lib/translation/translator.ts` (`translateTextBlocks` with Gemini 3.1 Pro / 2.5 Flash and DeepL fallback).
  - `lib/agents/05_translator.ts` (`TranslationAgent` dispatching batches with preserved placeholders and terminology glossary).
  - Edge worker: Direct Gemini API prompt requesting translated blocks for each detected coordinate box.
- **Rendering & Reconstruction**:
  - `lib/agents/06_renderer.ts` (`ReconstructionAgent` loading source PDF/image into `pdf-lib`, drawing white masking rectangles over source coordinates, scaling target fonts dynamically, and saving translated PDF bytes).
  - `lib/translation/pdf.ts` (`translatePdf` rendering with localized background inpainting and multi-column margin calculation).
  - `lib/translation/image.ts` (`translateImage` rendering with SVG/Jimp canvas).
  - Edge worker: `generateTranslatedSvg(job)` generating SVG overlays with `<rect fill="#ffffff"/>` masks and `<foreignObject>` text blocks.
- **Storage & Caching Stores**:
  - In-Memory Node Cache: `globalThis.__translationJobs` Map in `lib/translation/store.ts` (keyed by random `job.id`, 24h TTL).
  - Edge Global Cache: `globalThis.__vlJobs` Map in `scripts/build-cloudflare.js` (keyed by `jobId`).
  - Cloudflare Cache API: `caches.default` storing `/api/internal/jobs/{jobId}`.
  - Relational DB: Neon PostgreSQL via Prisma (`prisma.translationJob`).
  - Object Storage: AWS S3 / Cloudflare R2 bucket accessed through `lib/storage/index.ts` (`putObject`/`getObject`).
- **Frontend Fetching & Display**:
  - `app/translate/page.tsx`:
    - Manages file staging, language selection, upload triggering, and result display.
    - If upload returns `svgContent`, creates local blob URL: `URL.createObjectURL(new Blob([data.svgContent]))`.
    - Polls `GET /api/translate/status/${jobId}` every 800ms.
    - Resolves `translatedPreviewSrc`:
      - `translatedBlobUrl` (if set in component state)
      - else `/api/translate/download/${job.jobId}?token=${job.downloadToken}&inline=true&lang=${targetLang}`
      - else `/api/jobs/${job.jobId}/preview?lang=${targetLang}`
    - Displays in `<iframe src={translatedPreviewSrc}>` or `<img>`.

## 2. Current Pipeline Diagram

```text
[User File Upload]
       │
       ▼
[Frontend: app/translate/page.tsx]
       ├─► Heuristic Language Detection overrides (resets sourceLang/targetLang based on filename!)
       ├─► State: stagedFile, targetLang, translatedBlobUrl
       │
       ▼ (POST /api/translate/upload with multipart/form-data: file, sourceLang, targetLang)
[Upload Route / Edge Worker Router]
       │
       ├─► Generates random jobId (e.g., job_xxx) and downloadToken
       ├─► Validates MIME & size
       │
       ├─── Node.js Server Path:
       │      ├─► Saves source file to R2: `jobs/{userId}/{jobId}/source.{ext}`
       │      ├─► Reserves page credits in DB
       │      ├─► Orchestrator.processDocument:
       │      │     ├─► Gatekeeper: sanitize buffer
       │      │     ├─► Classifier: determine engine
       │      │     ├─► Extractor: extract bounding boxes from PDF streams / Jimp
       │      │     ├─► Glossary: lock protected tokens
       │      │     ├─► Translator: batch translation via Gemini/DeepL
       │      │     ├─► Renderer: pdf-lib mask & text draw into memory buffer
       │      │     └─► Inspector: QA checks
       │      ├─► Saves output PDF to R2: `jobs/{userId}/{jobId}/output.pdf`
       │      └─► Settle credits & update DB status="completed"
       │
       └─── Edge Worker Path:
              ├─► Calls Gemini Vision directly with fileBase64
              ├─► Parses returned blocks: box_2d, original_text, translated_text
              ├─► Generates SVG: `generateTranslatedSvg(job)`
              ├─► Stores in `globalThis.__vlJobs[jobId]`
              ├─► Caches in `caches.default.put('/api/internal/jobs/' + jobId)`
              └─► Returns HTTP 200 with { jobId, downloadUrl, svgContent } immediately!
       │
       ▼
[Frontend Polling & Result Reception]
       ├─► If svgContent in response: creates blob URL -> sets `translatedBlobUrl`
       ├─► If polling status: polls `GET /api/translate/status/${jobId}` until ready
       │
       ▼
[Frontend Render Stage]
       ├─► iframe / img src = translatedBlobUrl || `/api/translate/download/${jobId}?inline=true&lang=${targetLang}`
       └─► ResultViewer / DualPane workspace displays rendered artifact
```

## 3. Prime Suspect List (Every Place Results Are Keyed or Cached)

1. **Frontend Filename Auto-Detection Overwrite (`app/translate/page.tsx:261-274`)**:
   - `handleStageFile` inspects `file.name`. If it includes words like "beach", "reading", or "worksheet", it forces `setTargetLang("es")`!
   - When a user uploads the same file again intending to translate to French or German, the staging logic silently resets `targetLang` back to Spanish!
2. **Blob URL State Persistence (`app/translate/page.tsx:168-178, 388-394`)**:
   - `translatedBlobUrl` holds a client-side object URL (`blob:http...`). If the re-upload or language change does not synchronously clear this before the preview re-renders, the old SVG blob remains mounted.
3. **Download URL HTTP Cache Headers (`app/api/translate/download/[jobId]/route.ts:182`)**:
   - `Cache-Control: public, max-age=300` is returned when `inline=true`!
   - The browser or CDN caches the response for 5 minutes. If a request with the same URL (or browser iframe reload) is executed, the browser serves the 300-second cached representation.
4. **Lack of Composite Key in Output Storage (`app/api/translate/upload/route.ts:162`)**:
   - Source is stored under: `jobs/{userId}/{jobId}/source.{ext}`.
   - Output is stored under: `jobs/{userId}/{jobId}/output.{ext}`.
   - The output key does **not** incorporate `(document_content_hash, source_lang, target_lang, pipeline_version)`.
5. **Edge Worker In-Memory / Edge Cache Keyed Only on `jobId` (`scripts/build-cloudflare.js:1128, 1230`)**:
   - Cached in `caches.default` under `/api/internal/jobs/${jobId}`.
   - Svg output served at `/api/translate/download/${jobId}`.
   - If the frontend passes a stale or reused `jobId`, the previous language's SVG is returned.
6. **Download Route Target Language Fallback (`scripts/build-cloudflare.js:1242`)**:
   - `const targetLang = url.searchParams.get('lang') || (job && job.targetLang) || 'es';`
   - If `job.svgContent` is already present on the job object, `svgContent` is served directly without re-checking if the requested language matches the language inside `job.svgContent`.
